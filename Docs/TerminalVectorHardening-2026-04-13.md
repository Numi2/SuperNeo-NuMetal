# Terminal Vector Hardening Pass, 2026-04-13

This pass addresses a concrete artifact-coverage gap in the roadmap: checked-in
test vectors covered fold reductions, while complete terminal proofs were only
covered by CLI smoke tests.

## Finding

The repository had strict verifier context for checked-in fold vectors and a
production-gate terminal smoke test, but it did not have a pinned terminal proof
artifact with a manifest hash and strict `--require-terminal` verification
command. That left cross-version and cross-implementation consumers without a
stable complete-proof vector.

## Work Completed

- Added `TestVectors/one-hot-vector-terminal-v1.json`, generated by the real
  `superneo prove --kind terminal` CLI path for the one-hot workload.
- Added the terminal vector to `TestVectors/manifest.json` with its byte count,
  SHA-256 hash, expected public inputs, expected shape digest, expected statement
  digest, expected verifier-key digest, and strict verification command.
- Hardened `Scripts/validate-test-vectors.swift` so manifest entries whose
  `proofKind` is `terminal` automatically validate through `--require-terminal`.
- Documented the terminal vector in `TestVectors/README.md` and mapped it into
  `Docs/RoadmapStatus.md`.

Results: passed.

## Residual Boundaries

- The new vector is a complete proof for the one-hot workload only. The
  binary-addition workload still has a checked-in fold vector and release-gate
  smoke coverage, but not a checked-in terminal vector.
- Terminal proof vectors are intentionally large. The manifest hash and byte
  count are the compatibility boundary; digest changes should be treated as a
  serialization, transcript, normalization, or parameter compatibility event.
